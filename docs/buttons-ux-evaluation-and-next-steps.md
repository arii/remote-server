# S5 Buttons: UX Evaluation, Benchmark & Implementation Roadmap

> **Target Site:** `https://dev-onasafari.ddns.net:8443/buttons`  
> **Benchmark Reference:** `https://repo-auditor-ai.vercel.app/`  
> **Date:** October 2026  
> **Target File for Implementation:** `buttons/server.py`

---

## 1. Executive Summary & Purpose

The **S5 Buttons** service provides a phone-friendly, allowlisted action runner designed to eliminate the frustration of typing complex shell commands (`td`, `docker compose`, `jules`, `preflight`) on a smartphone touch keyboard. It runs directly on the Trigkey S5 home server behind GitHub OAuth and Caddy.

### Current Strengths:
- **Rock-Solid Safety:** Server-rendered buttons, strictly allowlisted command arguments, PTY streaming, and zero free-text command injection surface.
- **Durable Audit:** File-backed append-only JSONL ledger surviving container rebuilds.
- **Live Diagnostics:** Background polling with ANSI SGR color rendering and graceful rebuild reconnect logic.

### Core Problem ("Utility Wireframe Syndrome"):
While the server-side mechanics are production-grade, the user interface remains an unstyled single-column vertical feed. On mobile viewports:
- **Information Stacking:** 7+ distinct functional areas (stack controls, repo actions, PR cards, CI health, Pi suggestions, ledger, and session archives) compete for vertical space.
- **Output Invisibility:** The terminal output pane sits far below the fold. When tapping a command at the top of the screen, the user cannot see active streaming progress without manual scrolling.
- **Visual Monotony & Hazard Risk:** Safe, read-only queries (`Status`, `Preflight check`) have the exact same gray rectangular slab appearance as container-recreating actions (`Deploy buttons`, `Recreate terminal`).
- **Unformatted Data Spills:** Failing Dependabot runs spill dozens of unbroken npm package names across the viewport.
- **Client-Side Fragility:** A non-JSON or gateway error response triggers an unhandled `SyntaxError: Unexpected end of JSON input` that prints directly to the user.

## 2. Comparative Benchmark: S5 Buttons vs. RepoAuditor AI

| Dimension | S5 Buttons (`dev-onasafari.ddns.net:8443`) | RepoAuditor AI (`repo-auditor-ai.vercel.app`) | Recommended Pattern |
| :--- | :--- | :--- | :--- |
| **Information Architecture** | Flat, infinite single-page scroll with 7+ stacked sections. | Compartmentalized console with sidebar navigation (Overview, PRs, Workflow Health, Jules Management). | **Segmented Tab Control** (`Briefing`, `Actions`, `Pi Agent`, `Ledger`). |
| **Color & Theme** | Pure stark black (`#111`/`#000`) with high-contrast gray borders (`#555`). | Deep slate/navy palette (`#0B1120`, `#131D31`, `#1E293B`) with glowing blue & emerald accents. | **DevAI Slate/Navy Palette** with semantic status tokens. |
| **Repo Scoping** | Ambiguous top repo cards vs. middle dropdown picker. | Persistent active repo indicator (`arii/glossy`) with live status badge in the header. | **Sticky Top Header Bar** housing the active repo selector. |
| **PR & Issue Cards** | Plain text string blobs (`branch — CI: failing — merge: clean — updated...`) with raw buttons. | Scannable cards with badge chips (`#164`, branch chip, `+4 -4` diff chips, status indicators). | **Structured Badge Cards** separating metadata from action triggers. |
| **Action Hierarchy** | Centered text inside uniform gray rectangular slabs. | Distinct primary actions (blue filled button with icon) vs secondary outline/ghost actions. | **Card-Tile Buttons** with visual risk differentiation (amber borders on system actions). |
| **Terminal Output** | Fixed `<pre>` block pushed far below the buttons. | Clean status widgets, dismissible alert toasts, and collapsible log drawers. | **Slide-Up Bottom Output Drawer** docking into a compact status pill. |

## 3. Recommended Architectural Directions ("Best Guesses")

### 1. Navigation: 4-Tab Segmented Mobile Shell
Instead of an infinite scroll, group the interface into 4 dedicated tabs:
- **`📋 Briefing & PRs` (Default):** Live repo briefing, needs-attention alert, PR triage cards (with squash-merge, update-branch, and Jules fix buttons), and failing CI run breakdowns.
- **`⚡ Quick Actions`:** Repo-scoped tasks (`Repo briefing`, `Sync & nudge agents`, `Warm repo context`, `Preflight check`) plus a collapsible drawer for stack-level management (`Status`, `Deploy buttons`, `Recreate terminal`, `Logs`).
- **`🤖 Pi Agent`:** Allowlist-validated next-action suggestions generated by Pi, plus the Pi transcript session browser.
- **`📜 Audit Ledger`:** Filterable event stream (Runs, Webhooks, PR actions, System tombstones) and ledger clearing tools.

### 2. Output Log: Expandable Slide-Up Terminal Drawer
- Docked at the bottom of the viewport as a compact status pill:
  ```text
  [● Running] preflight check · step 1/2 · 14s elapsed  [Output ▴]
  ```
- Automatically slides open when the user triggers a run, and can be expanded/minimized at any time from any tab.
- Includes a dedicated `Clear Output` button and full ANSI color rendering without pushing content down the page.

### 3. Visual Styling: RepoAuditor AI Dark Navy Palette
- **Backgrounds:** Canvas `#0B1120`, Cards `#131D31`, Hover `#1E293B`, Borders `#24344D`.
- **Button Card Tiles:** Left-aligned bold labels with light-gray subtitles.
- **Hazard Accents:**
  - Standard/Safe: Dark slate card with blue hover.
  - System Destructive/Rebuilding (`deploy-buttons`, `recreate`): Amber accent border (`#F59E0B`).
  - Agent Sessions (`sync-nudge`, `suggestBtn`): Violet accent border (`#8B5CF6`).

### Phase 1: Robustness & Content Formatting Fixes

#### A. Safe JSON Fetching
Replace fragile `await r.json()` calls that crash when the server returns 504, 502, or plain text:
```javascript
async function fetchSafeJson(url, options = {}) {
  try {
    const res = await fetch(url, options);
    const text = await res.text();
    let data = null;
    try {
      data = JSON.parse(text);
    } catch {
      data = { error: text || `HTTP ${res.status}` };
    }
    return { ok: res.ok, status: res.status, data };
  } catch (err) {
    return { ok: false, status: 0, data: { error: err.message || "Network error" } };
  }
}
```
Update `refreshBriefing()` to use `fetchSafeJson()`, displaying a retry banner instead of a raw `SyntaxError`:
```javascript
async function refreshBriefing() {
  const picker = document.getElementById("briefingRepo");
  const repo = picker ? picker.value : "tech-dancer";
  briefingEl.innerHTML = '<span class="spinner"></span> Loading briefing…';
  briefingErrEl.textContent = "";

  const { ok, data } = await fetchSafeJson("/buttons/api/briefing?repo=" + encodeURIComponent(repo));
  if (!ok) {
    briefingEl.textContent = "";
    briefingErrEl.innerHTML = `
      <div class="alert-box">
        <span>Briefing unavailable: ${escHtml(data.error || "Unknown error")}</span>
        <button class="retry-btn" onclick="refreshBriefing()">Retry</button>
      </div>`;
    return;
  }
  renderBriefing(data);
}
```

const tabBtns = document.querySelectorAll(".tab-btn");
const tabPanels = document.querySelectorAll(".tab-panel");

function switchTab(tabId) {
  tabBtns.forEach(btn => btn.classList.toggle("active", btn.dataset.tab === tabId));
  tabPanels.forEach(panel => panel.classList.toggle("active", panel.id === tabId));
  try { localStorage.setItem("s5_active_tab", tabId); } catch (e) {}
}

tabBtns.forEach(btn => {
  btn.onclick = () => switchTab(btn.dataset.tab);
});

const savedTab = localStorage.getItem("s5_active_tab");
if (savedTab && document.getElementById(savedTab)) {
  switchTab(savedTab);
}

### Phase 4: Button Card Tiles & PR Badges

#### A. Left-Aligned Button Tiles in `_buttons_html()`
Update `_buttons_html()` in `buttons/server.py`:
```python
def _buttons_html():
    parts = []
    for group in ("Briefing", "Server"):
        btns = []
        for name, spec in ACTIONS.items():
            if spec["group"] != group or spec.get("hidden"):
                continue
            variant = "btn-tile"
            if name in ("deploy-buttons", "recreate"):
                variant += " btn-warning"
            elif name in ("sync-nudge", "agent-brief"):
                variant += " btn-agent"
            btns.append(
                f'<button class="{variant}" data-action="{escape(name)}" '
                f'data-confirm="{"1" if spec["confirm"] else "0"}" '
                f'data-label="{escape(spec["label"])}">'
                f'<span class="blabel">{escape(spec["label"])}</span>'
                f'<span class="bsub">{escape(spec["sub"])}</span></button>')
        if group == "Server":
            parts.append(
                f'<details class="server-drawer"><summary class="grouphead">'
                f'{GROUP_TITLES[group]}</summary><div class="btn-grid">{"".join(btns)}</div></details>')
        else:
            parts.append(
                f'<div class="grouphead">{GROUP_TITLES[group]}</div>'
                f'<div class="btn-grid">{"".join(btns)}</div>')
    return "".join(parts)
```
